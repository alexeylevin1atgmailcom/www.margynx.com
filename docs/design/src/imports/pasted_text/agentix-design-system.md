Design only the visual design language and reusable UI elements for a premium B2B SaaS product called Margynx Cockpit.

Do not design the website layout, sections, copy blocks, page structure, or final page composition.
Do not generate a homepage.
Do not decide content hierarchy.
Do not invent marketing messaging.
Only produce the design elements, component system, and style instructions that will later be applied to the website.

The design language must be derived from the attached cockpit reference image. The website will later be built separately, but it should visually feel like an extension of that cockpit.

Goal

Create a production-grade visual system that translates the cockpit’s aesthetic into a polished web design language for a serious SaaS marketing site.

The system should feel:
	•	premium
	•	precise
	•	futuristic but restrained
	•	technical and engineered
	•	trustworthy
	•	commercially credible

It must not feel like:
	•	gaming UI
	•	sci-fi movie props
	•	neon gimmick
	•	toy dashboard
	•	crypto landing page

Source of truth

Use the attached cockpit image as the primary style reference.

Extract from it:
	•	corner language
	•	frame language
	•	border logic
	•	glow behavior
	•	spacing rhythm
	•	display typography mood
	•	control styling
	•	panel chrome
	•	color accents

Required output

Produce a design system kit, not a page.

Include only these deliverables:

1. Shape language system

Define the geometric language used across the UI.

Create a consistent system for:
	•	clipped corners
	•	chamfered corners
	•	beveled diagonal cuts
	•	frame outlines
	•	panel edges
	•	header bars
	•	inner borders
	•	highlight lines

The shape language should clearly come from the cockpit image.

Important:
	•	avoid normal rounded SaaS rectangles
	•	avoid generic pill buttons
	•	avoid simple border-radius-based controls

Everything should look engineered and intentional.

2. Button system

Design reusable button variants only.

Create:
	•	primary CTA button
	•	secondary button
	•	tertiary / ghost button
	•	compact nav button
	•	icon button
	•	chip / tag / pill control

For each, define:
	•	shape
	•	border treatment
	•	fill treatment
	•	text style
	•	hover state
	•	active state
	•	focus state
	•	disabled state

All button corners should follow the same cockpit-style beveled/chamfered geometry.

3. Input and form control system

Design only the controls, not the page.

Create:
	•	text input
	•	email input
	•	password input
	•	dropdown
	•	segmented control
	•	checkbox
	•	radio button
	•	toggle
	•	search field
	•	filter chip

Each should inherit the same cockpit-inspired corner and border logic.

4. Card and panel system

Create reusable shells for:
	•	feature card
	•	clickable module card
	•	pricing card
	•	legal/info card
	•	image card
	•	modal shell
	•	tooltip shell
	•	section container
	•	floating CTA container

These should feel like web-adapted versions of the cockpit panels.

5. Navigation components

Design:
	•	top navigation bar style
	•	nav item style
	•	active nav state
	•	sticky header treatment
	•	right-side CTA in header
	•	mobile menu visual language

Do not create a full nav layout. Only provide component styling.

6. Typography system

Define the typography pairings and usage rules.

The heading style should match the cockpit title aesthetic:
	•	all-caps tech display font
	•	geometric / aerospace / futuristic sans
	•	medium to bold weight
	•	expanded letter spacing
	•	clean and precise

Possible families:
	•	Rajdhani
	•	Orbitron
	•	Exo 2
	•	Eurostile-style / Bank Gothic-style equivalents

Create rules for:
	•	hero display heading
	•	section heading
	•	card title
	•	label / overline
	•	body copy
	•	small caption
	•	italic sub-line

Important:
Use the futuristic display font only where appropriate:
	•	large headlines
	•	section titles
	•	control labels if elegant
Do not use it for paragraphs or dense body copy.

Also define the styling for this exact pairing:
Main line:
Your Amazon business, explained and operated in plain language.

Sub-line below it:
A seller cockpit that tells you what changed, why it changed, and what to do now.

The sub-line should be:
	•	smaller
	•	italic
	•	quieter
	•	visually subordinate
	•	like a refined shadow/supporting line, not a second headline

7. Color system

Create a restrained palette derived from the cockpit image.

Define:
	•	primary background
	•	elevated panel background
	•	header surface
	•	border color
	•	highlight blue
	•	accent cyan
	•	subtle green state
	•	subtle amber state
	•	subtle red state
	•	text primary
	•	text secondary
	•	muted text

The palette should feel like:
dark aerospace console + premium enterprise software

Avoid oversaturated neon.

8. Glow, border, and depth system

Define rules for:
	•	outer glow
	•	inner glow
	•	active outline
	•	focus ring
	•	border thickness
	•	layered borders
	•	shadows
	•	depth levels
	•	glass/panel transparency if used

The cockpit image uses illuminated edges. Translate that into a refined web system.

Important:
Glow should be subtle and premium.
Never loud or juvenile.

9. Iconography direction

Define icon style guidance only.

Icons should feel:
	•	technical
	•	clean
	•	minimal
	•	system-oriented
	•	slightly futuristic
	•	not playful

Specify stroke style, sizing logic, corner behavior, and whether icons should be line-based, filled, or hybrid.

10. Spacing and sizing rules

Define a consistent spacing system for:
	•	button heights
	•	card padding
	•	input heights
	•	nav spacing
	•	title spacing
	•	control density
	•	section shell padding

The system should feel precise and engineered, not airy in a generic startup way.

11. Motion guidance

Provide light motion principles for:
	•	hover
	•	press
	•	reveal
	•	panel activation
	•	focus
	•	sticky CTA behavior

Motion should feel:
	•	controlled
	•	precise
	•	responsive
	•	subtle
	•	like a system interface waking up

Not bouncy, playful, or soft.

Style constraints

The result must work for a marketing website, so it needs to be:
	•	elegant
	•	readable
	•	scalable
	•	production-friendly
	•	usable for conversion-focused UI

This is not a product dashboard UI kit.
It is a marketing-site visual language derived from the product cockpit UI.

Output format

Provide the result as a design system / UI kit / component library, including:
	•	reusable components
	•	style rules
	•	variants
	•	state definitions
	•	typography samples
	•	color tokens
	•	border/glow tokens
	•	corner geometry examples

Do not output page layouts or full web sections.

Most important instruction

Build the visual system so that later a separate process can apply it to a website.

So:
	•	provide components
	•	provide styling logic
	•	provide visual rules
	•	provide reusable shells

But do not compose the site itself.

And add this final note:

The website should later feel like it was built from the cockpit’s DNA, but with the restraint, clarity, and polish of a premium B2B SaaS brand.
